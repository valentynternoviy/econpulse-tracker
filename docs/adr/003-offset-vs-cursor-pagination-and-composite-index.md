# ADR-003. Серверна пагінація зі зміщенням для каталогу та складений індекс `(item_id, collected_at)`

Статус: прийнято, 2026-11-23

## Контекст
Каталог предметів підтримує комбінацію пошуку за назвою, фільтрів (гра, категорія, підкатегорія, рідкість, майданчик, діапазон цін) і довільного сортування (ціна за зростанням/спаданням, обсяг пропозицій, спред, зміна за 24 год), а також перехід на конкретну сторінку (`?page=`). Водночас таблиця історії цін `price_snapshots` містить ≥ 9 000 записів (і постійно зростає), тому вибірка історії предмета за 30 діб має виконуватися за десятки мілісекунд.

## Розглянуті варіанти
1) Курсорна пагінація (`keyset`) для каталогу предметів — стабільна під час вставок і швидка на великих зміщеннях, але складна у поєднанні з довільним сортуванням за обчислюваними показниками (поточна ціна, спред, обсяг) і не дозволяє перейти на довільний номер сторінки (`page=3`), як зазначено в сигнатурі API з ТЗ (`GET /api/v1/items?...&page=`).
2) Пагінація зі зміщенням (`LIMIT/OFFSET`) зі стабільним вторинним сортуванням за `items.id` для каталогу (де кілька сотень–тисяч записів), у поєднанні зі складеним B-tree індексом `(item_id, collected_at DESC)` на таблиці `price_snapshots` для запитів часових рядів.

## Рішення
Застосувати серверну пагінацію `page` / `page_size` (`LIMIT/OFFSET` із детермінованим tie-breaker `items.id ASC`) для каталогу предметів та додати складений індекс `ix_price_snapshots_item_collected` за полями `(item_id, collected_at)` (а також індекс за `(item_id, market_id, collected_at)` для пошуку останнього знімка на майданчику).

## Наслідки
Позитивні:
- повна відповідність контракту API (`?page=`) та можливість переходу на будь-яку сторінку з виведенням `total` і `pages`;
- детермінований порядок без дублювання чи пропуску записів на межах сторінок;
- побудова графіка історії за 30 діб використовує `Index Scan` замість `Seq Scan`, що зменшує час запиту в рази.

Негативні:
- при масштабуванні каталогу до мільйонів записів глибокі зміщення (`OFFSET 100000`) почнуть деградувати;
- додаткові складені індекси дещо збільшують обсяг сховища і витрати на вставку нових знімків.

## Умова перегляду
Якщо кількість активних предметів у каталозі перевищить 100 000 і користувачі масово гортатимуть глибокі сторінки — перейти на курсорну пагінацію для стрічок.
